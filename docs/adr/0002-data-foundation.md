# ADR 0002: Data foundation (models, sources, settings storage)

- Status: accepted
- Date: 2026-10-17

## Context
Phase 1 adds the shared models, the first two agenda sources and persistent settings. Several choices affect
battery, privacy, Direct Boot and future migrations, and are not obvious from the code.

## Decision
- **Time types:** `kotlinx-datetime` 0.8 for dates and zones, and `kotlin.time.Instant` for timestamps (stable in
  Kotlin 2.4). An item keeps the precision its source has: all-day (zone-independent dates), timed (instants)
  or due (local date with an optional time).
- **Privacy by construction:** `AgendaItem`, `CalendarInstanceRow` and `LocalTaskEntity` override `toString` to
  redact titles, so accidental logging cannot leak user content.
- **Calendar Provider:** the source queries `CalendarContract.Instances` for the requested window and listens with a
  `ContentObserver`. It never polls, and bursts of change notifications are conflated. All-day events are read
  in UTC, because that is how the provider stores them. Without `READ_CALENDAR`, the source emits a failure and
  completes; it never requests the permission itself.
- **Room 3 with the platform SQLite driver:** `AndroidSQLiteDriver` (`sqlite-framework`) instead of the bundled
  SQLite. This keeps native libraries out of the APK (CLAUDE.md §5).
- **`-Xexpect-actual-classes` in `data`:** Room's KMP database constructor is an `expect object` whose `actual`
  is generated by KSP. Kotlin marks expect/actual classes as Beta and warns unless this flag opts in. With
  warnings-as-errors, that warning would fail the build. The flag only accepts a Beta language feature; it
  does not hide deprecations. Remove it when expect/actual classes are stable (KT-61573).
- **Settings format:** one versioned JSON envelope, `{"schemaVersion": N, "settings": {...}}`, used both on
  device and for import/export. Migrations transform raw JSON step by step. Decoding ignores unknown keys,
  maps unknown enum values to defaults, clamps out-of-range numbers, and refuses files from newer app versions.
- **Settings location:** DataStore, in **device-protected storage**, so the wallpaper can read settings before
  the first unlock. Settings contain no secrets. The Todoist token, when it arrives, is stored separately and
  encrypted. A corrupt file falls back to defaults.
- **Room schema files** are committed under `data/schemas/`. CI fails, and prints the generated files, when
  they are missing or stale.

## Consequences
- A settings change that renames or repurposes a field needs a `SettingsMigration` and a
  `SettingsCodec.CURRENT_VERSION` bump. Adding a field with a default needs neither.
- Downgrading the app after a settings schema bump resets settings to defaults (newer files are rejected).
- Local tasks are unavailable before the first unlock (credential-protected storage). The wallpaper must render
  from its cached scene then (Phase 2).
